# 第一切片总体设计 V0.1

文档名称：第一切片总体设计  
系统名称：面向动力电池回收利用企业的流转协同与追溯管理系统  
设计范围：回收接收 -> 电池登记 -> 验收 -> 入库 -> 库存可见  
当前阶段：system-design  
当前检查点：设计评审  
文档状态：待评审  
输入基线：C2 全局业务基线 V1.0、C3 第一条业务切片定义 V1.0、C4 第一切片需求与原型基线 V1.0  
边界说明：本文只定义第一切片总体设计，不编写正式前端业务代码、正式后端业务代码或全系统实现。

## 1. 设计目标和范围

第一切片总体设计的目标是将 C4 已确认的需求、测试和低保真原型转换为可指导后续开发的技术基线。设计必须支撑回收批次创建、电池包登记、重复原始编码核实、提交验收、验收登记、资料补充、入库办理、库存查询、生命周期追溯和审计记录。

本阶段纳入：

- 前后端分离的模块化单体架构。
- 第一切片模块职责和依赖。
- 状态转换、事务边界、并发和幂等原则。
- 权限、审计、追溯和异常处理原则。
- 数据库、API、安全和部署设计的引用关系。
- 重复原始编码候选登记模型和写接口幂等持久化模型。

本阶段排除：

- 企业间流转、接收企业确认、综合利用和真实监管平台连接。
- 正式前端工程、正式后端工程和生产业务代码。
- 全系统数据库扩展和第一切片以外的表结构。
- 真实检测设备、真实二维码打印设备和移动端。

## 4. 系统上下文和参与角色

第一切片服务于企业内部回收、验收和仓储入库流程。外部来源主体只作为回收来源信息进入系统，不在第一切片中登录或协同操作。

| 角色 | 系统职责 |
| --- | --- |
| 回收操作员 | 创建回收批次、登记电池包、处理重复原始编码、提交验收、登记验收和补充资料。 |
| 仓库管理员 | 查询待入库电池、办理入库、查询库存和追溯。 |
| 业务主管 | 查看业务状态、库存和追溯，不代替操作员办理第一切片业务。 |
| 系统管理员 | 管理角色权限、查看审计，不代替业务角色完成验收或入库。 |
| 无权限用户 | 不具备业务操作权限，所有业务操作默认拒绝并审计。 |

## 8. 核心业务流程

1. 回收操作员登录系统并创建回收批次。
2. 系统生成批次编号，保存来源必填信息和选填信息。
3. 回收操作员登记电池包，系统生成全局唯一系统追溯编码。
4. 原始编码为空或不重复时继续创建有效电池档案；原始编码疑似重复时只创建候选登记，不生成第二份有效档案。
5. 人工核实为同一电池时关闭候选并使用原档案；核实为不同电池时记录原因，再创建新电池档案并生成新系统追溯编码。
6. 回收操作员将有效电池加入批次并提交验收。
7. 系统整体校验批次和电池状态，提交成功后批次进入待验收，电池进入待验收。
8. 回收操作员登记验收结果。
9. 验收通过时电池进入已验收待入库；待补充资料时进入待补充资料；不通过时进入验收不通过。
10. 待补充资料电池补充资料后重新回到待验收。
11. 仓库管理员对已验收待入库电池选择有效仓库和库位办理入库。
12. 系统生成入库记录和当前库存记录，电池进入在库。
13. 用户查询库存和生命周期追溯时间线。

## 9. 状态转换实现原则

状态转换必须由后端服务层统一处理，前端不得直接决定最终状态。每次状态转换应包含：

- 当前状态条件判断。
- 目标状态计算。
- 状态条件更新或乐观锁校验。
- 业务记录写入。
- 生命周期事件写入。
- 必要审计日志写入。

失败的业务操作不得改变批次、电池、库存或验收记录状态。

## 10. 事务边界

| 事务 | 原子操作 |
| --- | --- |
| 提交批次 | 整体校验、批次状态更新、电池状态更新、生命周期事件、审计日志。 |
| 保存验收 | 验收记录、电池状态、批次状态、生命周期事件、审计日志。 |
| 补充资料 | 补充资料记录、电池状态恢复、生命周期事件、审计日志。 |
| 办理入库 | 入库记录、库存记录、电池状态、生命周期事件、审计日志。 |
| 幂等写接口 | 幂等记录、目标业务记录、首次响应记录。 |

所有事务使用数据库事务提交。发生校验失败、权限失败、唯一约束冲突、乐观锁失败或状态条件更新失败时整体回滚。

写接口必须持久化 `Idempotency-Key`。相同键和相同请求体返回首次处理结果；相同键但请求体不同返回 `IDEMPOTENCY_KEY_REUSED`，不得执行业务操作。

## 11. 权限和审计原则

- URL 层和方法层都必须校验权限。
- 未授权操作默认拒绝。
- 业务主管和系统管理员不能绕过业务角色职责代替办理验收或入库。
- 越权操作、失败入库、删除保护和权限变更写入审计日志。
- 审计日志保存操作者、操作时间、对象类型、对象编号、动作、结果、失败原因和 traceId。

## 12. 异常处理原则

| 异常 | 处理原则 | 错误码 |
| --- | --- | --- |
| 来源必填缺失 | 拒绝提交或保存，状态不变。 | BATCH_REQUIRED_FIELD_MISSING |
| 空批次提交 | 拒绝提交，批次保持草稿。 | BATCH_EMPTY |
| 原始编码重复 | 创建候选登记，进入人工核实，不创建第二份有效档案。 | BATTERY_ORIGINAL_CODE_DUPLICATE |
| 幂等键复用冲突 | 拒绝执行并返回冲突。 | IDEMPOTENCY_KEY_REUSED |
| 未核实重复档案加入批次 | 拒绝加入或提交，状态不变。 | BATTERY_DUPLICATE_UNRESOLVED |
| 非法状态验收或入库 | 拒绝操作，状态不变。 | INVALID_BATTERY_STATE |
| 验收必填缺失 | 拒绝保存，批次和电池状态不变。 | ACCEPTANCE_REQUIRED_FIELD_MISSING |
| 仓库或库位停用 | 拒绝入库并审计。 | WAREHOUSE_DISABLED、LOCATION_DISABLED |
| 库位与仓库不匹配 | 拒绝入库并审计。 | LOCATION_WAREHOUSE_MISMATCH |
| 越权操作 | 拒绝并审计。 | FORBIDDEN_OPERATION |
| 删除已生效记录 | 拒绝并审计。 | EFFECTIVE_RECORD_DELETE_FORBIDDEN |
| 重复提交 | 拒绝或返回既有结果，状态不重复推进。 | DUPLICATE_SUBMISSION |

## 13. 非功能需求实现方式

| NFR | 实现方式 |
| --- | --- |
| NFR-C4-001 追溯性 | 状态变化和关键业务活动写入 `lifecycle_event`。 |
| NFR-C4-002 失败状态保持 | 校验全部通过后才执行状态更新；状态更新使用事务和条件更新。 |
| NFR-C4-003 权限默认拒绝 | Spring Security + 权限编码 + 方法级鉴权。 |
| NFR-C4-004 生效记录保护 | 关键业务表不物理删除，删除请求转为拒绝审计。 |
| NFR-C4-005 原型边界 | 原型仅作需求验证，正式开发以本技术设计和后续评审为准。 |
