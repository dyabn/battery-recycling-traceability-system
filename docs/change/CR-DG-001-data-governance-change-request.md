# CR-DG-001 数据治理能力变更请求 V1.1

文档状态：已确认
提出日期：2026-09-22
修订日期：2026-09-23
目标基线：V1.1
评审结论：复核通过
处理决定：批准
批准基线：V1.1

## 1. 变更原因

当前系统已经具备业务追溯、审计、编码、数据字典和技术设计 V1.0 基础。为提升第一业务切片数据的可信度，拟增加轻量级数据治理能力，用于对已产生的回收、登记、验收、入库和库存数据执行事后质量检查，发现问题并推动处理闭环。

## 2. 变更目标

在不推翻第一业务切片 V1.0 的前提下，增加固定规则、手工检查、质量问题、处理复核和看板汇总能力，形成可验证的数据治理最小闭环。

## 3. 变更范围

- 固定规则及其数据标准元数据。
- 数据质量规则启用和停用。
- 手工质量检查任务。
- 质量问题生成和去重。
- 问题分配、处理、重新检查和关闭。
- 数据质量状态汇总看板。
- 数据治理低保真原型实际评审记录。

## 4. 排除范围

- 数据湖。
- 大数据平台。
- 独立数据标准管理平台。
- 复杂元数据平台。
- 自动血缘解析。
- AI 自动修复。
- 区块链。
- 真实监管平台。
- 自定义脚本规则引擎。
- 在线编辑规则算法、字段或判断表达式。

## 5. 影响分析

| 影响项 | 初步影响 |
| --- | --- |
| 业务需求 | 新增 `UR-DG`、`FR-DG`、`NFR-DG`、`AC-DG`，不覆盖原 `UR-C4`、`FR-C4`、`AC-C4`。 |
| 用户角色 | 复用系统管理员、业务主管、回收操作员和仓库管理员；不新增“数据治理专员”或通用“管理人员”。 |
| 数据库 | V1.1 技术设计阶段预计新增规则、检查任务、质量问题、整改记录等表；本阶段不冻结表结构。 |
| API | V1.1 技术设计阶段预计新增规则、检查任务、质量问题处理和看板接口；本阶段不冻结接口。 |
| 页面 | 新增规则列表、发起检查、检查结果、问题列表、问题详情、分配责任人、处理复核和看板页面。 |
| 权限 | 需要新增规则查看、规则启停、检查执行、问题分配、问题处理、复核关闭和看板查看权限。 |
| 测试 | 新增 `TC-DG`，覆盖规则启停、手工检查、问题状态、去重、权限、企业隔离、审计和看板口径。 |
| 部署 | V1.1 需求基线不引入新基础设施；定时任务、消息队列和异步调度暂不纳入。 |
| 项目工期 | 正式实现分支继续延后，需要先完成 V1.1 需求、原型和技术设计评审。 |

## 6. 评审问题处理结果

| 编号 | 处理结果 |
| --- | --- |
| DG-Q-001 | V1.1 固定规则默认启用；系统管理员只能只读查看规则、问题、看板和审计，不得配置规则、处理问题或执行复核。 |
| DG-Q-002 | 业务主管分配问题；回收操作员和仓库管理员处理各自业务问题；业务主管重新检查并关闭；处理人不能自行关闭严重问题。 |
| DG-Q-003 | V1.1 只支持手工发起质量检查；原业务实时校验继续保留，但不作为治理检查任务。 |
| DG-Q-004 | DQ-001 至 DQ-007 进入第一版；DQ-008 临时附件规则延期。 |
| DG-Q-005 | 已生效数据不得直接覆盖；必须通过业务更正或调整记录处理，并在质量问题中关联更正记录。 |
| DG-Q-006 | 必须有整改证据、同一规则重新检查通过、业务主管复核和完整审计，问题才能关闭。 |

## 7. 最终复核修订摘要

- DQ-001..DQ-007 已按 V1.0 SQL 和数据字典字段重新校对。
- DQ-001 改为全系统唯一，结果按当前企业权限过滤。
- DQ-002 改用 `current_responsible_enterprise_id`，并明确不得仅凭说明关闭。
- DQ-003 对齐 `candidate_status` 和 `review_result`。
- DQ-004 对齐 `acceptance_result`、`lifecycle_status`、`inbound_status`、`inbound_at` 和 `lifecycle_event.occurred_at`。
- DQ-005 明确比较 `inbound_record.warehouse_id` 与 `warehouse_location.warehouse_id`。
- DQ-006 改用 `occurred_at` 并删除豁免。
- DQ-007 对齐 `current_responsible_enterprise_id` 和 `inventory.is_current=1`。
- V1.1 不实现问题豁免；豁免能力登记为后续版本候选项。
- 低保真原型已修复规则启停、企业隔离、检查结果、审计结构和看板统计。
- 已新增实际原型评审记录。

## 8. 处理决定

批准。

CR-DG-001 已复核通过，数据治理需求、测试设计和低保真原型确认为 V1.1 需求基线。允许进入数据治理 V1.1 技术设计评审；仍不得创建正式实现分支，不得编写生产前后端代码，不得执行正式数据库迁移，不得覆盖或破坏技术设计 V1.0。
