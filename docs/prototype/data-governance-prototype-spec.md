# 数据治理低保真原型规格 V0.2

文档状态：修改后复核
关联变更：CR-DG-001
目标基线：V1.1

## 1. 原型定位

本原型用于验证数据治理需求，不是正式前端代码。原型只覆盖轻量级数据治理闭环，不改变第一业务切片 V1.0 原型和技术设计基线。

## 2. 页面清单

| 编号 | 页面 | 目标 |
| --- | --- | --- |
| UI-DG-001 | 数据质量规则列表 | 查看固定规则、数据标准元数据、启用状态，并验证规则启停原因和权限。 |
| UI-DG-002 | 发起质量检查 | 选择检查范围、结果场景并启动手工检查。 |
| UI-DG-003 | 检查结果 | 查看检查任务状态、结果摘要、无问题、失败和重复去重结果。 |
| UI-DG-004 | 质量问题列表 | 按状态、责任人、规则筛选问题并选择具体问题。 |
| UI-DG-005 | 问题详情 | 查看问题对象、规则、描述、责任人、状态、处理证据和审计历史。 |
| UI-DG-006 | 分配责任人 | 由业务主管分配处理人，验证未检查、跨企业和无权限拦截。 |
| UI-DG-007 | 处理与重新检查 | 责任人开始处理、提交说明和证据，业务主管重新检查通过或失败。 |
| UI-DG-008 | 数据质量看板 | 按企业和默认最近 30 天查看规则数量、检查次数、问题数量、关闭率和未关闭问题。 |

## 3. 主要用户流程

```text
业务主管进入数据质量
-> 查看规则
-> 发起检查
-> 查看检查结果
-> 选择具体问题
-> 分配质量问题
-> 责任人处理
-> 业务主管重新检查
-> 关闭或退回
-> 看板更新
```

正常状态流：

```text
OPEN -> ASSIGNED -> PROCESSING -> SUBMITTED -> RECHECKING -> CLOSED
```

失败后重新处理：

```text
RECHECKING -> REJECTED -> PROCESSING -> SUBMITTED -> RECHECKING -> CLOSED
```

## 4. 原型验证场景

| 编号 | 场景 | 预期 |
| --- | --- | --- |
| REVIEW-DG-001 | 查看并启停质量规则 | 可以看到固定规则和数据标准元数据；系统管理员填写原因后可以启停，非管理员被拒绝。 |
| REVIEW-DG-002 | 重置后无问题 | 重置后检查次数、问题数量和看板问题数均为 0。 |
| REVIEW-DG-003 | 发起有问题检查 | 检查任务生成并完成，按检查范围生成质量问题。 |
| REVIEW-DG-004 | 发起无问题检查 | 检查完成但不生成质量问题。 |
| REVIEW-DG-005 | 检查失败 | 记录失败原因，不生成质量问题，不计入完成检查次数。 |
| REVIEW-DG-006 | 重复问题去重 | 同一规则和对象已有未关闭问题时，重复检查不新增问题。 |
| REVIEW-DG-007 | 分配责任人 | 选择具体问题并分配后，问题状态变为 `ASSIGNED`。 |
| REVIEW-DG-008 | 状态保护 | 未分配、非责任人、缺少说明或证据时，提交处理被拒绝且状态不变。 |
| REVIEW-DG-009 | 正常闭环 | 问题依次进入 `PROCESSING`、`SUBMITTED`、点击开始重新检查后进入 `RECHECKING`，通过后进入 `CLOSED`。 |
| REVIEW-DG-010 | 失败后重新处理 | 点击开始重新检查后进入 `RECHECKING`，失败后进入 `REJECTED`，责任人可重新处理并再次提交。 |
| REVIEW-DG-011 | 已关闭保护和再次违规 | 已关闭问题不能编辑；再次违规时可生成新问题。 |
| REVIEW-DG-012 | 权限和企业隔离 | 无权限或跨企业操作被拒绝，状态保持不变并写审计。 |
| REVIEW-DG-013 | 查看看板 | 看板按企业展示启用规则数、完成检查次数、问题数量、关闭率和未关闭问题。 |
| REVIEW-DG-014 | 审计历史 | 审计包含操作者、时间、对象、动作、前后状态、结果和原因。 |

## 5. 原型位置

静态低保真原型位于：

```text
prototype/data-governance/
```

可直接打开 `index.html` 查看，不需要后端、数据库或正式前端工程。
