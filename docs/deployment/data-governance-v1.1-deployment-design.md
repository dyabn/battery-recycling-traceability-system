# 数据治理 V1.1 部署与运行设计

文档状态：待评审
关联变更：CR-DG-001

## 1. 部署边界

V1.1 数据治理能力作为现有单体后端的增量模块部署，不新增独立服务、不引入消息队列、不引入大数据平台。

运行组件：

- PC Web 前端后续实现复用现有前端工程。
- 后端单体新增 `MOD-DATA-QUALITY`。
- MySQL 8.4 新增 8 张数据治理表。
- 现有审计、幂等、附件、权限模块继续复用。

## 2. 环境变量

| 变量 | 用途 | 默认 |
| --- | --- | --- |
| `DQ_DEFAULT_DASHBOARD_DAYS` | 看板默认统计天数。 | `30` |
| `DQ_CHECK_RUN_TIMEOUT_SECONDS` | 检查任务超时时间。 | `300` |
| `DQ_IDEMPOTENCY_TTL_SECONDS` | 幂等记录保留周期。 | 继承 V1.0 |

## 3. 运行策略

- 质量检查 V1.1 仅支持手工触发。
- 检查任务在业务请求内串行执行；后续如数据量扩大，可演进为异步任务。
- 检查失败不生成质量问题。
- 检查失败不计入看板完成检查次数。
- 默认看板查询最近 30 天数据。

## 4. 数据迁移策略

- 本阶段只提供迁移 SQL 设计稿。
- 技术评审通过前不得在生产库执行。
- 验证环境使用 GitHub Actions MySQL 8.4 服务执行增量 SQL。
- 迁移失败不得修改 `project-state.yaml` 为通过。

## 5. 回滚策略

由于 V1.1 尚未进入正式实施，本阶段仅定义设计回滚原则：

- 新增表可在测试库回滚。
- 不修改 V1.0 表结构。
- 不影响 V1.0 第一切片已确认技术设计。
- 规则初始化失败时不允许上线数据治理入口。

## 6. 监控与日志

后续实现阶段至少记录：

- 检查任务耗时。
- 检查任务失败原因。
- 质量问题生成数量。
- 规则启停操作。
- 跨企业拒绝次数。
- 幂等冲突次数。

## 7. 当前结论

部署设计待评审。评审通过前不得执行正式迁移或部署。
