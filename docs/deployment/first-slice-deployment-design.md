# 第一切片部署设计 V1.0

文档名称：第一切片部署设计
系统名称：面向动力电池回收利用企业的流转协同与追溯管理系统
当前阶段：system-design
当前检查点：设计评审
文档状态：已确认
边界说明：本文定义后续实现阶段的部署基线，不创建正式工程、不编写部署脚本。

## 1. 部署目标

第一切片部署设计需要支持本地开发、课程演示和后续测试环境运行。部署方式采用前后端分离、单体后端、MySQL 8 和可选 Docker Compose，不引入微服务或复杂中间件。

## 2. 本地开发环境

| 组件 | 地址 |
| --- | --- |
| 前端 | `http://localhost:5173` |
| 后端 | `http://localhost:8080` |
| MySQL | `localhost:3306` |
| Swagger | `http://localhost:8080/swagger-ui.html` |

## 3. 环境划分

| 环境 | 用途 | 配置原则 |
| --- | --- | --- |
| `dev` | 本地开发和调试 | 可使用本地 MySQL，日志级别较详细。 |
| `test` | 测试和评审 | 使用独立数据库，初始化固定测试数据。 |
| `prod` | 课程最终演示或部署 | 关闭调试日志，配置独立密钥、备份和健康检查。 |

不同环境使用不同配置文件或环境变量，不把生产密钥提交到仓库。

## 4. 配置项

| 配置项 | 示例 | 说明 |
| --- | --- | --- |
| `SPRING_PROFILES_ACTIVE` | `dev` | 后端运行环境。 |
| `DB_HOST` | `localhost` | 数据库主机。 |
| `DB_PORT` | `3306` | 数据库端口。 |
| `DB_NAME` | `battery_traceability` | 数据库名称。 |
| `DB_USERNAME` | `battery_app` | 数据库用户。 |
| `DB_PASSWORD` | 环境变量注入 | 数据库密码，不提交。 |
| `JWT_SECRET` | 环境变量注入 | JWT 签名密钥，不提交。 |
| `ATTACHMENT_STORAGE_DIR` | `./data/uploads` | 附件存储目录。 |
| `LOG_DIR` | `./logs` | 日志目录。 |
| `VITE_API_BASE_URL` | `http://localhost:8080/api/v1` | 前端 API 基础路径。 |

## 5. 数据库初始化

- MySQL 8 使用 `utf8mb4` 字符集。
- 后续正式实现使用 Flyway 管理迁移。
- 设计版 SQL 位于 `contracts/database/first-slice-schema-design.sql`，正式迁移脚本需从设计版 SQL 转换并编号。
- 初始数据至少包括企业、角色、权限、用户、仓库和库位。

## 6. Flyway 迁移规划

| 脚本 | 内容 |
| --- | --- |
| `V1__create_first_slice_schema.sql` | 创建第一切片核心表、约束和索引。 |
| `V2__seed_permissions_and_roles.sql` | 初始化权限编码、角色和角色权限关系。 |
| `V3__seed_demo_enterprise_users_warehouse.sql` | 初始化演示企业、用户、仓库和库位。 |

本阶段不创建正式 Flyway 文件，只定义迁移规划。

## 7. 前端打包

- 开发阶段使用 Vite dev server。
- 测试和演示环境使用 `npm run build` 生成静态文件。
- 静态文件由 Nginx 托管。
- 前端配置通过环境变量或构建时变量指定 API 地址。

## 8. Nginx 反向代理

建议规则：

```text
/               -> 前端静态文件
/api/v1/        -> 后端 Spring Boot
/swagger-ui/    -> 后端 Swagger
```

生产或演示环境建议启用 HTTPS。课程本地演示可使用 HTTP。

## 9. 健康检查

后端应提供健康检查端点：

```text
GET /actuator/health
```

健康检查至少覆盖：

- 应用进程是否存活。
- 数据库连接是否可用。
- 附件目录是否可写。

## 10. 日志设计

- 应用日志输出到 `LOG_DIR`。
- 日志包含 traceId、请求路径、用户 ID、企业 ID、结果和耗时。
- 审计日志保存到数据库 `audit_log`。
- 不在日志输出密码、JWT、JWT 密钥、数据库密码。
- 生产环境按天滚动日志。

## 11. 附件存储

- 附件文件存储在 `ATTACHMENT_STORAGE_DIR`。
- 数据库只保存附件元数据和存储路径。
- 文件名使用服务端生成名称，不直接使用用户上传名称作为真实路径。
- 附件目录需要纳入备份计划。

## 12. 备份和恢复

| 对象 | 策略 |
| --- | --- |
| MySQL 数据库 | 每日逻辑备份；课程演示可手动备份。 |
| 附件目录 | 与数据库备份同周期保留。 |
| 配置 | 环境变量和部署说明单独保存，不提交密钥。 |
| 恢复验证 | 测试环境定期验证数据库和附件恢复。 |

## 13. 首次管理员初始化

首次部署需要初始化：

- 一个演示企业。
- 系统管理员账号。
- 回收操作员、仓库管理员和业务主管账号。
- 权限编码和角色权限关系。
- 有效仓库 `WH-001`。
- 有效库位 `WH-001-A01-R01-L01`。
- 一个停用仓库或库位用于异常测试。

初始化数据应通过 Flyway seed 脚本或后端启动初始化任务完成，禁止硬编码在业务逻辑中。

## 14. Docker Compose 可选设计

后续实现阶段可提供 `docker-compose.yml`，包含：

- `mysql`：MySQL 8。
- `backend`：Spring Boot 应用。
- `frontend` 或 `nginx`：前端静态资源和反向代理。

本阶段仅确认可选部署方式，不创建正式 Compose 文件。
