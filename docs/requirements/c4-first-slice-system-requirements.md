# C4 第一切片系统需求规格 V0.1

文档名称：C4 第一切片系统需求规格  
系统名称：面向动力电池回收利用企业的流转协同与追溯管理系统  
切片名称：回收接收 -> 电池登记 -> 验收 -> 入库 -> 库存可见  
当前阶段：prototype-and-requirements  
当前关口：C4  
文档状态：待评审  
输入基线：C2 全局业务基线 V1.0、C3 第一条业务切片定义 V1.0  
边界说明：本文只定义第一切片的系统需求、字段、权限、校验、追溯和审计要求，不设计正式数据库、API 或生产代码。

## 3. 功能需求

| 编号 | 功能需求 | 对应用户需求 | 对应验收标准 |
| --- | --- | --- | --- |
| FR-C4-001 | 系统应在创建回收批次时自动生成批次编号，并自动记录当前企业、创建人、创建时间和批次状态。 | UR-C4-001 | AC-001 |
| FR-C4-002 | 系统应校验回收批次来源类型、来源主体名称和交接日期；来源类型为企业时必须填写来源企业。 | UR-C4-001 | AC-001、AC-004 |
| FR-C4-003 | 系统应允许交接地点、关联单据号、交接人员、备注和附件为空。 | UR-C4-001 | AC-001 |
| FR-C4-004 | 系统应在登记电池包时生成全局唯一系统追溯编码，并维护当前责任企业和生命周期状态。 | UR-C4-002 | AC-002、AC-012 |
| FR-C4-005 | 系统应支持录入原始编码；原始编码为空时允许继续登记。 | UR-C4-002 | AC-002 |
| FR-C4-006 | 系统应在原始编码与既有有效档案重复时标记为疑似重复，禁止直接建立新的有效档案。 | UR-C4-003 | AC-003 |
| FR-C4-007 | 系统应支持人工核实重复原始编码：同一电池使用原档案，不同电池生成新追溯编码并记录重复原因和处理人。 | UR-C4-003 | AC-003 |
| FR-C4-008 | 系统应支持将已完成登记且有效的电池加入回收批次，并阻止无效档案或未核实疑似重复档案加入。 | UR-C4-004 | AC-003、AC-004 |
| FR-C4-009 | 系统应在提交验收时执行批次整体校验；批次必须至少包含一个有效电池包，且任一电池登记无效时整批提交失败。 | UR-C4-004 | AC-004 |
| FR-C4-010 | 系统应在批次提交成功后，将批次内全部有效电池状态置为“待验收”。 | UR-C4-004 | AC-004、AC-012 |
| FR-C4-011 | 系统应支持登记验收结果为“通过”，并将电池状态变更为“已验收待入库”。 | UR-C4-005 | AC-005 |
| FR-C4-012 | 系统应支持登记验收结果为“待补充资料”，且必须填写需要补充资料的说明。 | UR-C4-005、UR-C4-006 | AC-006 |
| FR-C4-013 | 系统应支持补充资料后重新提交验收，并保留前一次资料不足记录。 | UR-C4-006 | AC-007 |
| FR-C4-014 | 系统应支持登记验收结果为“不通过”，且必须填写不通过原因。 | UR-C4-005 | AC-008 |
| FR-C4-015 | 系统应阻止验收不通过、待补充资料或非“已验收待入库”状态的电池办理正常入库。 | UR-C4-007 | AC-008、AC-009 |
| FR-C4-016 | 系统应在入库时要求选择已启用仓库和已启用库位，且库位必须属于所选仓库。 | UR-C4-007 | AC-009、AC-010 |
| FR-C4-017 | 系统应在入库确认后生成入库记录和有效库存记录，并将电池状态变更为“在库”。 | UR-C4-007 | AC-010 |
| FR-C4-018 | 系统应支持按系统追溯编码查询库存，并显示当前责任企业、仓库、库位和状态。 | UR-C4-008 | AC-011 |
| FR-C4-019 | 系统应为登记、提交验收、资料补充、验收通过、验收不通过、入库成功和业务状态变化生成生命周期事件。 | UR-C4-008 | AC-012 |
| FR-C4-020 | 系统应将越权操作、入库失败、删除失败等安全或失败操作写入审计日志。 | UR-C4-009 | AC-012、AC-013 |
| FR-C4-021 | 系统应按角色控制创建批次、电池登记、验收登记、入库办理、库存查询、权限管理等操作。 | UR-C4-009 | AC-013 |
| FR-C4-022 | 系统应阻止物理删除或直接覆盖已生效回收批次、验收记录、入库记录、库存记录和生命周期事件。 | UR-C4-010 | AC-014 |

## 7. 状态和校验要求

### 7.1 电池包状态转换

| 当前状态 | 操作 | 下一状态 | 校验要求 |
| --- | --- | --- | --- |
| 无档案 | 登记电池包 | BAT-01 已登记 | 系统追溯编码唯一；原始编码重复时先核实。 |
| BAT-01 已登记 | 提交验收 | BAT-02 待验收 | 所属批次来源完整，批次至少一个有效电池。 |
| BAT-02 待验收 | 验收通过 | BAT-05 已验收待入库 | 验收结果明确。 |
| BAT-02 待验收 | 待补充资料 | BAT-03 待补充资料 | 必须填写补充资料说明。 |
| BAT-03 待补充资料 | 补充资料并重新提交 | BAT-02 待验收 | 保留前一次资料不足记录。 |
| BAT-02 待验收 | 验收不通过 | BAT-04 验收不通过 | 必须填写不通过原因。 |
| BAT-05 已验收待入库 | 办理入库 | BAT-06 在库 | 必须选择启用仓库和库位。 |

### 7.2 回收批次状态转换

```text
草稿 -> 待验收 -> 验收处理中 -> 已完成
```

| 状态 | 进入条件 | 退出条件 |
| --- | --- | --- |
| 草稿 | 批次创建后默认状态。 | 来源必填信息完整，且至少包含一个有效电池，提交验收成功。 |
| 待验收 | 批次提交成功，批次内电池进入待验收。 | 任一电池开始登记验收结果。 |
| 验收处理中 | 存在待验收或待补充资料电池。 | 批次内所有电池均取得通过或不通过的最终结果。 |
| 已完成 | 批次内所有电池取得最终验收结果。 | 第一切片不定义重新打开批次。 |

### 7.3 关键校验

| 编号 | 校验项 | 失败结果 |
| --- | --- | --- |
| VAL-C4-001 | 来源类型、来源主体名称、交接日期必填。 | 拒绝提交验收，批次和电池状态不变。 |
| VAL-C4-002 | 批次至少包含一个有效电池包。 | 拒绝提交验收，批次保持草稿。 |
| VAL-C4-003 | 任一电池登记无效时整批提交失败。 | 批次和所有电池状态保持不变。 |
| VAL-C4-004 | 原始编码重复未核实时不得建立新的有效档案。 | 标记疑似重复并提示人工核实。 |
| VAL-C4-005 | 待补充资料时必须填写说明。 | 拒绝保存验收结果。 |
| VAL-C4-006 | 验收不通过时必须填写原因。 | 拒绝保存验收结果。 |
| VAL-C4-007 | 只有“已验收待入库”电池可办理入库。 | 拒绝入库。 |
| VAL-C4-008 | 入库必须选择启用仓库和启用库位。 | 拒绝入库。 |
| VAL-C4-009 | 库位必须属于所选仓库。 | 拒绝入库。 |
| VAL-C4-010 | 已生效记录不能直接删除或覆盖。 | 拒绝删除或覆盖并提示更正流程。 |
