# 数据治理需求规格 V1.1

文档状态：已确认
关联变更：CR-DG-001
目标基线：V1.1

## 1. 用户需求

| 编号 | 用户需求 | 角色 |
| --- | --- | --- |
| UR-DG-001 | 作为系统管理员，我需要查看、启用和停用第一版固定质量规则，以便控制系统按统一标准检查数据。 | 系统管理员 |
| UR-DG-002 | 作为业务主管，我需要发起质量检查，以便发现业务数据中的质量问题。 | 业务主管 |
| UR-DG-003 | 作为业务主管，我需要查看检查结果和问题列表，以便判断问题严重程度和责任人。 | 业务主管 |
| UR-DG-004 | 作为责任人，我需要提交问题处理说明或更正结果，以便推动质量问题闭环。 | 回收操作员、仓库管理员、业务主管 |
| UR-DG-005 | 作为业务主管，我需要重新检查并关闭已解决问题，以便保证问题关闭有依据。 | 业务主管 |
| UR-DG-006 | 作为业务主管，我需要查看数据质量状态汇总，以便了解整体数据质量状态。 | 业务主管 |

## 2. 功能需求

| 编号 | 功能需求 | 对应用户需求 |
| --- | --- | --- |
| FR-DG-001 | 系统应展示固定质量规则列表，包括规则编号、名称、维度、适用对象、数据标准元数据、参与字段、判断条件、严重程度、默认责任角色、启用状态和是否允许豁免；V1.1 中 DQ-001..DQ-007 均不允许豁免。 | UR-DG-001 |
| FR-DG-002 | 系统应允许系统管理员启用或停用固定规则；启停必须填写原因并记录审计。 | UR-DG-001 |
| FR-DG-003 | 系统不得允许在线修改规则算法、字段、判断表达式或编写脚本。 | UR-DG-001 |
| FR-DG-004 | 系统应允许业务主管手工发起质量检查任务，并选择检查范围。 | UR-DG-002 |
| FR-DG-005 | 系统应记录检查任务的发起人、发起时间、状态、检查范围、启用规则集合和结果摘要。 | UR-DG-002 |
| FR-DG-006 | 系统应支持检查无问题和检查失败两类结果；检查失败不得生成质量问题。 | UR-DG-002 |
| FR-DG-007 | 系统应根据检查结果生成质量问题，记录规则、对象、问题描述、严重程度和默认责任角色。 | UR-DG-003 |
| FR-DG-008 | 同一企业、同一规则、同一对象已有未关闭问题时，重复检查不得重复创建相同问题；已关闭后再次违规可以创建新问题。 | UR-DG-003 |
| FR-DG-009 | 系统应允许业务主管将质量问题分配给责任人。 | UR-DG-003 |
| FR-DG-010 | 系统应执行状态保护：`OPEN -> ASSIGNED -> PROCESSING -> SUBMITTED -> RECHECKING -> CLOSED`，失败分支为 `RECHECKING -> REJECTED -> PROCESSING -> SUBMITTED`。 | UR-DG-003..005 |
| FR-DG-011 | 系统应允许责任人开始处理本人被分配的问题。 | UR-DG-004 |
| FR-DG-012 | 系统应允许责任人提交处理说明、附件或关联更正记录；没有说明或证据不得提交。 | UR-DG-004 |
| FR-DG-013 | 系统不得允许非责任人提交处理，不得允许处理人自行关闭严重问题。 | UR-DG-004 |
| FR-DG-014 | 系统应允许业务主管仅对 `SUBMITTED` 状态问题发起重新检查，重新检查开始时进入 `RECHECKING`。 | UR-DG-005 |
| FR-DG-015 | 系统应在重新检查通过后关闭问题；未通过时退回 `REJECTED`，允许责任人重新处理。 | UR-DG-005 |
| FR-DG-016 | 系统应禁止编辑已关闭问题；再次违规必须通过新检查生成新问题。 | UR-DG-005 |
| FR-DG-017 | 系统应提供质量状态汇总看板，展示规则数量、检查次数、问题数量、关闭率和未关闭问题。 | UR-DG-006 |
| FR-DG-018 | 系统应记录规则启停、质量检查、问题生成、分配、处理、复核、关闭、权限拒绝和跨企业拒绝审计。 | UR-DG-001..006 |

## 3. 非功能需求

| 编号 | 非功能需求 | 验证方式 |
| --- | --- | --- |
| NFR-DG-001 | 数据治理操作不得直接物理覆盖原始业务记录。 | 测试和评审 |
| NFR-DG-002 | 质量问题状态变化必须可追踪、可审计。 | 测试 |
| NFR-DG-003 | 数据质量接口必须遵守企业数据隔离和角色权限控制。 | 测试 |
| NFR-DG-004 | 第一版质量规则采用固定规则，不提供脚本表达式引擎。 | 评审 |
| NFR-DG-005 | 检查范围必须影响实际检查对象；失败操作必须保持原状态不变。 | 测试 |

## 4. 第一版质量规则

| 编号 | 规则 | 是否进入 V1.1 | 说明 |
| --- | --- | --- | --- |
| DQ-001 | 系统追溯编码必须唯一 | 是 | 严重，业务主管处理。 |
| DQ-002 | 电池核心字段必须完整 | 是 | 一般，回收操作员处理。 |
| DQ-003 | 原始编码重复必须完成核实 | 是 | 严重，回收操作员处理。 |
| DQ-004 | 未验收通过的电池不能入库 | 是 | 严重，业务主管处理；用于事后核对。 |
| DQ-005 | 库位必须属于所选仓库 | 是 | 严重，仓库管理员处理；用于事后核对。 |
| DQ-006 | 生命周期事件时间不能倒序 | 是 | 一般，业务主管处理；V1.1 不支持豁免。 |
| DQ-007 | 当前库存责任企业必须一致 | 是 | 严重，仓库管理员处理。 |
| DQ-008 | 已过期临时附件不能绑定 | 延期 | 不进入第一版。 |

完整规则字段、检查条件、通过条件、失败条件和整改方式见 `docs/business/data-governance-first-slice.md`。

V1.1 不实现问题豁免。豁免申请、审批、撤销及统计作为后续版本候选项，不进入当前需求草案。

## 5. 验收标准

| 编号 | Given / When / Then |
| --- | --- |
| AC-DG-001 | Given 系统已初始化固定质量规则 When 系统管理员查看规则列表 Then 可以看到规则编号、名称、维度、对象、数据标准元数据和启用状态。 |
| AC-DG-002 | Given 系统管理员填写启停原因 When 启用或停用固定规则 Then 规则状态更新并记录审计。 |
| AC-DG-003 | Given 非系统管理员或未填写原因 When 尝试启停规则 Then 系统拒绝操作，规则状态保持不变。 |
| AC-DG-004 | Given 已存在第一业务切片数据 When 业务主管选择检查范围并发起质量检查 Then 系统生成检查任务和结果摘要。 |
| AC-DG-005 | Given 检查未发现违规数据 When 检查任务完成 Then 系统记录合格结果，不生成质量问题。 |
| AC-DG-006 | Given 检查执行失败 When 检查任务结束 Then 系统记录失败原因，不生成质量问题。 |
| AC-DG-007 | Given 检查发现违规数据 When 检查任务完成 Then 系统生成质量问题并关联规则和业务对象。 |
| AC-DG-008 | Given 同一规则和对象已有未关闭问题 When 重复执行检查 Then 系统不重复创建相同未关闭问题。 |
| AC-DG-009 | Given 存在未分配质量问题 When 业务主管分配责任人 Then 问题状态变为 `ASSIGNED` 并记录审计。 |
| AC-DG-010 | Given 问题已分配 When 责任人开始处理并提交处理说明和证据 Then 状态依次变为 `PROCESSING` 和 `SUBMITTED`。 |
| AC-DG-011 | Given 问题未分配、非责任人操作或缺少处理证据 When 提交处理 Then 系统拒绝操作，状态保持不变。 |
| AC-DG-012 | Given 问题已提交处理 When 业务主管重新检查通过 Then 状态先变为 `RECHECKING`，再变为 `CLOSED`。 |
| AC-DG-013 | Given 问题已提交处理但仍违规 When 业务主管重新检查不通过 Then 状态变为 `REJECTED`，责任人可重新处理。 |
| AC-DG-014 | Given 问题不是 `SUBMITTED` 或问题已关闭 When 发起重新检查或编辑问题 Then 系统拒绝操作，状态保持不变。 |
| AC-DG-015 | Given 存在检查任务和质量问题 When 业务主管查看质量状态汇总 Then 系统按企业和默认最近 30 天展示规则数量、检查次数、问题数量、关闭率和未关闭问题。 |
| AC-DG-016 | Given 用户无权限或访问其他企业问题 When 执行业务操作 Then 系统拒绝操作，状态保持不变并记录审计。 |

## 7. 看板指标口径

| 指标 | 口径 |
| --- | --- |
| 规则数量 | 当前企业启用规则数。 |
| 检查次数 | 默认最近 30 天内状态为 `COMPLETED` 的检查任务数；检查失败不计入。 |
| 问题数量 | 默认最近 30 天内发现的问题数。 |
| 未关闭问题 | 状态不为 `CLOSED` 的问题数。 |
| 关闭率 | 已关闭问题数 / 已发现问题总数。 |

所有指标按企业隔离。第一版只展示质量状态汇总，不做趋势图。

## 9. 当前结论

本需求已确认为 V1.1 需求基线。允许进入数据治理 V1.1 技术设计评审；仍不得创建正式实现分支，不得编写生产业务代码。
