# 数据治理需求规格 V0.1

文档状态：待评审
关联变更：CR-DG-001
目标基线：V1.1

## 1. 用户需求

| 编号 | 用户需求 | 角色 |
| --- | --- | --- |
| UR-DG-001 | 作为系统管理员，我需要查看第一版固定质量规则，以便确认系统按统一标准检查数据。 | 系统管理员 |
| UR-DG-002 | 作为业务主管，我需要发起质量检查，以便发现业务数据中的质量问题。 | 业务主管 |
| UR-DG-003 | 作为业务主管，我需要查看检查结果和问题列表，以便判断问题严重程度和责任人。 | 业务主管 |
| UR-DG-004 | 作为责任人，我需要提交问题处理说明或更正结果，以便推动质量问题闭环。 | 回收操作员、仓库管理员、业务主管 |
| UR-DG-005 | 作为业务主管，我需要重新检查并关闭已解决问题，以便保证问题关闭有依据。 | 业务主管 |
| UR-DG-006 | 作为管理人员，我需要查看数据质量看板，以便了解整体数据质量状态。 | 管理人员 |

## 2. 功能需求

| 编号 | 功能需求 | 对应用户需求 |
| --- | --- | --- |
| FR-DG-001 | 系统应展示固定质量规则列表，包括规则编号、名称、维度、适用对象、启用状态。 | UR-DG-001 |
| FR-DG-002 | 系统应允许业务主管发起手工质量检查任务。 | UR-DG-002 |
| FR-DG-003 | 系统应记录检查任务的发起人、发起时间、状态、检查规则范围和结果摘要。 | UR-DG-002 |
| FR-DG-004 | 系统应根据检查结果生成质量问题，记录规则、对象、问题描述和严重程度。 | UR-DG-003 |
| FR-DG-005 | 系统应允许业务主管将质量问题分配给责任人。 | UR-DG-003 |
| FR-DG-006 | 系统应允许责任人提交处理说明、附件或关联更正记录。 | UR-DG-004 |
| FR-DG-007 | 系统应允许业务主管对已提交处理的问题发起重新检查。 | UR-DG-005 |
| FR-DG-008 | 系统应在重新检查通过后关闭问题；未通过时退回继续处理。 | UR-DG-005 |
| FR-DG-009 | 系统应提供质量看板，展示规则数量、检查次数、问题数量、关闭率和未关闭问题。 | UR-DG-006 |
| FR-DG-010 | 系统应记录质量检查、分配、处理、复核和关闭操作审计。 | UR-DG-002..006 |

## 3. 非功能需求

| 编号 | 非功能需求 | 验证方式 |
| --- | --- | --- |
| NFR-DG-001 | 数据治理操作不得直接物理覆盖原始业务记录。 | 测试和评审 |
| NFR-DG-002 | 质量问题状态变化必须可追踪、可审计。 | 测试 |
| NFR-DG-003 | 数据质量接口必须遵守企业数据隔离和角色权限控制。 | 测试 |
| NFR-DG-004 | 第一版质量规则采用固定规则，不提供脚本表达式引擎。 | 评审 |

## 5. 验收标准

| 编号 | Given / When / Then |
| --- | --- |
| AC-DG-001 | Given 系统已初始化固定质量规则 When 系统管理员查看规则列表 Then 可以看到规则编号、名称、维度、对象和启用状态。 |
| AC-DG-002 | Given 已存在第一业务切片数据 When 业务主管发起质量检查 Then 系统生成检查任务和结果摘要。 |
| AC-DG-003 | Given 检查发现违规数据 When 检查任务完成 Then 系统生成质量问题并关联规则和业务对象。 |
| AC-DG-004 | Given 存在未分配质量问题 When 业务主管分配责任人 Then 问题状态变为 `ASSIGNED` 并记录审计。 |
| AC-DG-005 | Given 问题已分配 When 责任人提交处理说明 Then 问题状态变为 `SUBMITTED`。 |
| AC-DG-006 | Given 问题已提交处理 When 业务主管重新检查通过 Then 问题状态变为 `CLOSED`。 |
| AC-DG-007 | Given 问题已提交处理 When 重新检查不通过 Then 问题状态变为 `REJECTED` 并要求继续处理。 |
| AC-DG-008 | Given 存在检查任务和质量问题 When 管理人员查看质量看板 Then 系统展示检查次数、问题数量、关闭率和未关闭问题。 |
